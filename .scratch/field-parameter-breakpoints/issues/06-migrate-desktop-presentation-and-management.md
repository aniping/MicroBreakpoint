# 06 — 迁移桌面端展示与管理

**What to build:** 让桌面用户能够清晰查看和管理 Agent 创建的字段参数断点，以分组条件行表达 AND 语义，同时保留接口级命令断点创建能力并移除旧参数快照创建体验。

**Blocked by:** 03 — 完成规则身份、生命周期与模式切换。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 桌面端统一使用“字段参数断点”术语，不再显示“条件断点”或“参数快照断点”等旧称呼。
- [ ] 规则卡以“匹配以下全部条件”分组展示结构化条件行，不把多个条件拼成包含“且”的长句。
- [ ] `eq` 和 `contains_any` 使用简洁、一致的操作符标签；bool 与列表候选以易扫描的紧凑值样式展示。
- [ ] 用户可以展开查看规则的规范化条件 JSON，同时默认卡片保持简洁。
- [ ] 列表继续显示规则状态、命中次数和最近命中信息。
- [ ] 用户可以启用、停用和删除字段参数断点，并正确反映后端的模式切换和生命周期结果。
- [ ] 桌面端不提供字段参数断点的创建或编辑入口，旧参数快照创建动作被移除。
- [ ] 接口级命令断点的创建、展示和管理继续正常工作。
- [ ] UI 测试覆盖命名、AND 分组、条件行、值样式、展开 JSON 和管理动作，但不在前端重复测试匹配器语义。
