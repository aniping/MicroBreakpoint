# 08 — 完成跨仓库验收与文档收口

**What to build:** 对 MicroBreakpoint 与 AteAgents 的完整字段参数断点流程做最终验收，证明两个后端、MCP 工具和桌面管理使用同一已发布契约，接口级断点没有回归，并让用户文档准确描述最终可用行为。

**Blocked by:** 07 — 删除旧参数匹配及旧存储结构。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 通过 MicroBreakpoint 的公开生命周期完整演示 `eq` 深层字段匹配、多条件 AND、`contains_any`、多规则 OR、模式切换、命中解释和 Session 生命周期。
- [ ] 同一组行为向量在 Java 与 Flask 上全部通过，且两端对规范化、结构化错误、暂停身份和解释结果一致。
- [ ] AteAgents 能从有证据的用户意图生成 MCP 参数，经 HITL 批准后创建规则，并根据规范化响应及最近调用观测核验结果。
- [ ] 桌面端能够清晰展示和管理 Agent 创建的规则，且不提供本期范围外的字段规则创建或编辑能力。
- [ ] 接口级命令断点的声明、创建、暂停、管理和回归测试全部通过，不受参数级条件要求影响。
- [ ] 执行两个仓库与改动相关的聚焦测试、完整后端测试、MCP/V3 契约测试及桌面构建或测试；如有无法执行项，记录具体原因和替代证据。
- [ ] README 和直接相关的用户文档说明支持的类型、两个操作符、深层路径、AND/OR 语义、列表限制、Session 行为、Agent 禁止猜测及桌面能力边界。
- [ ] 文档明确排除请求/响应修改、数组寻址、额外操作符、旧数据兼容和其他本期范围外能力。
- [ ] 最终差异不包含生成物、缓存、临时文件或两个仓库中与本需求无关的用户改动。
