# 04 — 补全创建反馈与命中解释

**What to build:** 让 Agent 和调试用户在声明字段参数断点后立即看到后端实际保存的规则、发生的状态变化以及目标接口的有限观测信息，并能用与运行时完全一致的语义解释每个条件为什么命中或未命中。

**Blocked by:** 03 — 完成规则身份、生命周期与模式切换。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 成功声明返回稳定规则标识、已布防状态和完整规范化规则，不要求调用方反推后端保存结果。
- [ ] 返回结果明确区分新建、复用和重新启用，并列出因模式冲突而被停用的接口级规则标识。
- [ ] 允许在接口尚未被观测时声明规则；结果明确标记未观测状态，但规则仍正常布防。
- [ ] 已观测目标返回有界的接口摘要，包括当前 Session 内调用次数和最后观测时间。
- [ ] 存在相关调用时，仅返回最近一次调用的逐条件观测，包括字段是否存在、实际类型、有界预览和按当前规则计算的匹配结果。
- [ ] 声明结果不扫描或返回全部调用历史，也不返回无界的原始参数负载。
- [ ] 命中说明能够表达逐条件结果、整体 AND 结果和稳定原因码，并覆盖缺失路径、类型不兼容及列表无交集等非命中原因。
- [ ] 每个后端的运行时暂停、最近调用观测和命中说明复用该后端的同一匹配语义，不能产生互相矛盾的结论。
- [ ] Java 与 Flask 对声明反馈、已观测与未观测场景、有界预览及解释原因输出保持一致。
