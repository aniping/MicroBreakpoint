# 02 — 加入 `contains_any` 列表任一匹配

**What to build:** 在字段参数断点的完整声明与运行时闭环中加入列表任一匹配，让用户指定的一组基本类型候选值能够命中实际请求列表中的任意等值基本类型元素，同时对混合 JSON 列表保持稳定和可预测。

**Blocked by:** 01 — 打通字段参数断点 `eq` 最小纵切。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] `contains_any` 只接受非空候选列表，候选项只允许数字、字符串和 bool，并对空列表、null、对象、嵌套列表等输入返回结构化校验错误。
- [ ] 候选值按集合语义规范化：顺序和重复项不影响规则语义，数值相等的整数和小数折叠为同一候选值。
- [ ] 实际字段必须是列表；只要其中任意基本类型元素与任意候选值完全匹配，条件即命中。
- [ ] 实际列表可以混合任意 JSON 类型，其中对象、嵌套列表和 null 被忽略，不导致异常或错误命中。
- [ ] 实际值不是列表、实际列表为空或不存在匹配的基本类型元素时，条件安全地不匹配。
- [ ] 数字、字符串和 bool 沿用 `eq` 的完全匹配规则，不发生跨类型强制转换。
- [ ] 公开 HTTP 生命周期能够演示类似实际值 `[1, 2, 3, 4]` 与候选值 `[4, 5]` 的暂停行为，以及无交集时的继续行为。
- [ ] Java 与 Flask 通过同一组行为向量验证候选规范化、混合列表、数值等价、无交集和错误输入。
