# 03 — 完成规则身份、生命周期与模式切换

**What to build:** 让字段参数断点能够可靠表达多字段 AND 和多规则 OR，并在重复声明、重新启用、模式冲突、Session 清理及重复命中时保持确定的规则身份和生命周期行为。

**Blocked by:** 02 — 加入 `contains_any` 列表任一匹配。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 每条字段参数断点至少包含一个条件，同一路径最多出现一次；条件顺序不影响规范化结果或规则身份，所有条件按 AND 组合。
- [ ] 同一 Session、业务对象和命令下可以同时启用多条字段参数规则，各规则之间按 OR 处理。
- [ ] 规则身份由 Session、业务对象、命令、内部匹配模式和规范化条件共同决定；显示名称和来源说明不参与身份判断。
- [ ] 重复声明等价规则复用原规则标识；如果等价规则已停用，则重新声明会重新启用，而不是创建副本。
- [ ] 接口级规则与字段参数规则对同一目标互斥；创建或启用一种模式时停用另一种模式的已启用规则，但不删除它们。
- [ ] 多条字段参数规则同时匹配时，最早创建的规则是唯一暂停原因，也只有该规则增加命中次数。
- [ ] 字段参数规则持续生效，每次匹配调用都暂停，直到规则被停用、删除或随 Session 删除；本需求不提供一次性或命中次数策略。
- [ ] 规则限定于一个 Session；省略 Session 时使用当前 Session，没有当前 Session 时返回错误。
- [ ] 清除调用记录保留规则；清空或删除 Session 删除该 Session 的规则。
- [ ] 同一业务参数在不同合成槽位值下得到相同匹配结果，且槽位字段不能作为虚拟字段路径使用。
- [ ] 通用断点 API 与 Agent API 使用相同的字段规则规范化和校验入口，不能通过不同入口绕过约束。
- [ ] Java 与 Flask 的公开生命周期测试覆盖 AND、OR、幂等、重新启用、双向模式切换、获胜规则、连续命中和 Session 生命周期。
