# 01 — 打通字段参数断点 `eq` 最小纵切

**What to build:** 让调用方能够声明一条使用 `eq` 的字段参数断点，并在真实业务调用进入 before-call 生命周期时，依据完整原始请求参数决定继续或暂停。这个最小闭环必须同时适用于 Java 与 Flask 后端，并且不改变接口级命令断点的既有行为。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 字段参数断点使用新的内部模式；接口级断点仍使用既有接口模式，且无条件声明和暂停行为保持不变。
- [ ] 一条 `eq` 条件只接受 `field_path`、`operator`、`value`，要求显式提供操作符，并拒绝多余字段、旧别名和不受支持的操作符。
- [ ] `eq` 的期望值只接受数字、字符串或 bool；不接受 null、对象或列表。
- [ ] 支持 `a.b.c` 形式的深层对象路径，并拒绝空段、首尾点、重复点、JSONPath、数组下标和需要转义的路径。
- [ ] 数字按精确数值匹配，整数与等值小数可命中；字符串保留大小写和空白；bool 不与数字或字符串互相转换。
- [ ] 缺失字段、非对象中间节点、不支持的实际类型和非对象顶层参数均安全地视为不匹配，不抛出影响业务调用的异常。
- [ ] 匹配只读取 before-call 阶段的完整原始 `params`，不读取预览、摘要、持久化裁剪结果，也不注入或过滤合成槽位字段。
- [ ] 通过公开 HTTP 生命周期可验证声明、匹配调用暂停、不匹配调用继续、规则查询和基础命中说明。
- [ ] Java 与 Flask 使用同一组行为向量覆盖规范化、校验、深层路径、基本类型完全匹配和安全不匹配。
