# 07 — 删除旧参数匹配及旧存储结构

**What to build:** 在所有调用方都迁移到字段参数断点后，完成 expand–contract 的收缩阶段，彻底移除旧参数快照和旧字段条件实现，使运行时代码、API、存储、测试及文档只剩一个规范化字段参数断点模型。

**Blocked by:** 05 — 迁移 AteAgents 的 `declare_breakpoint` MCP 契约；06 — 迁移桌面端展示与管理。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 删除旧参数快照模式、旧参数条件模式及其匹配分支，不保留运行时兼容入口。
- [ ] 删除旧路径别名、旧操作符、请求/响应前缀、槽位过滤和仅服务于旧匹配器的转换逻辑。
- [ ] 存储只保留确定性的规范化条件表示；删除旧快照、指纹、负载引用和旧条件拆列等专用字段。
- [ ] API 不接受旧字段、旧别名或旧模式，不实现迁移、备份、schema 版本兼容或自动数据库重建机制。
- [ ] 如果实现时发现仓库内确有一个旧数据库文件，只删除该明确文件并由新 schema 重建；不存在则不执行任何数据库删除操作。
- [ ] 删除或重写只验证旧行为的测试，保留并加强接口级断点回归和新字段参数断点契约测试。
- [ ] 清理用户文档、Agent 指引和桌面文案中的旧参数匹配术语及示例，不顺手改写无关内容。
- [ ] 代码搜索确认已删除本需求约定淘汰的模式名、存储字段和兼容别名；确需保留的历史文字必须说明原因。
- [ ] Java、Flask、MCP 与桌面端在收缩后仍通过各自相关测试，不依赖任何旧参数匹配实现。
